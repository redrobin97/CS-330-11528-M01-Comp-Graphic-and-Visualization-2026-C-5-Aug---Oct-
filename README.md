CS 330 Project Reflection


How do I approach designing software?

When designing software, I like to break larger problems into smaller, manageable pieces. Throughout this project, I learned how important it is to plan how different objects will be built and how they will interact within a scene. I started with basic shapes and gradually combined them to create more complex objects, including a laptop, coffee mug, bottle, and desk lamp. One of the most useful design skills I developed was learning how to think about objects in three dimensions, especially when working with positioning, scaling, and rotation.

My design process involved building one object at a time, testing how it looked, and making adjustments before moving on. I also separated my objects into their own rendering functions, which made the code easier to organize and modify. This approach is something I can apply to future projects because breaking complex problems into smaller components makes development and debugging much more manageable.


How do I approach developing programs?

My approach to developing programs is to get something functional first and then improve it through iteration. This project reinforced that approach because many of my objects went through several changes before I was satisfied with them. For example, I originally attempted to create individual keyboard keys using loops, but eventually decided that a keyboard texture would produce a better result without unnecessary complexity. I also made several adjustments to my lamp's geometry and lighting to get the appearance I wanted.

Throughout the milestones, I became more comfortable experimenting with the code and understanding how different changes affected the scene. Early on, I was primarily focused on getting shapes positioned correctly, but later I was working with textures, materials, lighting, and camera controls. I also implemented the ability to switch between perspective and orthographic views, which required understanding how different projection methods affect the scene. By the end of the project, I was much more confident making changes without needing to rebuild or rewrite large portions of my code.


How can computer science help me in reaching my goals?

My long-term goal is to work as a software engineer, and this project gave me experience with an area of programming I had not explored much before. Most of my previous experience has been focused on web development and more traditional programming problems, so working with OpenGL and computational graphics introduced me to new concepts.

Although I do not currently plan to specialize in computer graphics, the skills I developed are still valuable. Working with transformations, coordinate systems, rendering, and lighting helped strengthen my understanding of mathematics in programming. The project also gave me more experience with C++ and organizing larger programs into reusable functions.

Professionally, I think the most valuable takeaway is the experience of taking a project from a basic starting point to a completed application through multiple stages of development. Being able to break down problems, experiment with solutions, and improve existing code are skills that will be useful regardless of which area of software engineering I eventually pursue.
